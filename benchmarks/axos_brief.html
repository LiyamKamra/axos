SIH 2026 · Problem statement 119 · sovereign optimization solver

AXOS: LP, QP and MILP solvers built from scratch, with their own GPU kernels

Every algorithm in AXOS is its own C++17 code, from the simplex and interior-point methods to the first-order GPU methods and branch and cut. No optimization library sits underneath, and the QP and MILP GPU kernels are AXOS's own, without cuBLAS or cuSPARSE. AXOS was benchmarked against nine established solvers on the standard test sets, under the same rules, with every answer re-checked independently.

How AXOS was built and measured

Building it

  1. Algorithms from the literature

    HPR-QP (Chen, Sun, Yuan, Zhang, Zhao 2025) and PDHCG (Huang et al. 2025) for QP, Mehrotra's interior point, the bounded dual simplex, and branch and cut with the MILP techniques of the problem statement: GPU probing and propagation, feasibility jump, the feasibility pump, batched GPU LP bounds, Gomory and c-MIR cuts, reliability branching, RENS and RINS.

  2. Written independently in C++17

    Every method is AXOS's own code. The authors' Julia packages served only as comparators. The CPU version of each method came first and became the reference for the GPU version.

  3. GPU kernels in measured stages

    The GPU work went from one kernel per vector operation, to fused kernels replayed as CUDA graphs, to removing FP64 divisions and coalescing memory access. Every stage was timed per iteration on the same problems.

  4. Correctness first

    Every change was checked against known optima and reference solutions. The MILP solver accepts a solution only after checking it on the original, non-presolved model.

Benchmarking it

  1. Standard test sets

    QP: the 138 Maros–Meszaros problems, plus 14 generated problems with 1–4 million nonzeros. MILP: MIPLIB 2017, using the 50 smallest "easy" benchmark instances and 16 larger ones, with the MIPLIB reference values.

  2. Established comparators

    QP: PIQP, Clarabel, SCS, OSQP, HiGHS and the authors' GPU codes HPR-QP.jl and PDHCG.jl. MILP: HiGHS 1.15.1, SCIP 10.0 and CBC 2.10.3.

  3. Same rules for everyone

    One machine for everything. QP solvers ran one at a time; MILP solvers ran single-threaded, at most two at once on the 16-thread CPU. All solvers got the same tolerance (QP 1e-6 relative KKT; MILP relative gap 1e-4) and the same time limit (QP 60 s and 120 s; MILP 60 s). Each instance ran in its own process, with a kill timer and a memory guard.

  4. Scored by us, not by the solvers

    QP answers are re-scored with one common KKT metric. MILP solutions are re-checked on the original model through HiGHS' reader and compared with MIPLIB's best known values. The ranking measures are solved counts, shifted geometric mean time (SGM10) and primal gap.

  5. Audited

    The power log was checked for standby during runs, and runs that might have been affected were redone. Two problems in the CBC adapter, its time limit and its solution file, were found, fixed and CBC re-run. All scripts are in benchmarks/, so every number can be reproduced.

The interface

One command-line solver and one C++ header for LP, QP and MILP. The problem type comes from the model file: integer markers mean MILP, a quadratic section means QP. A Python wrapper calls the same executable and returns its JSON report.

C++ and Python

// C++: header only, src/solver/api.h
#include "solver/api.h"
using namespace AXOS::Solver;

Model m = read_model("plant.mps");
Options o;
o.time_limit = 60;        // method, device, tol, gap ...
Result r = solve(m, o);   // status, objective, bound, x, y
std::cout << result_json(m, r);
# Python: apps/axos.py
import axos
r = axos.solve("plant.mps", time_limit=60, device="gpu")
print(r["status"], r["objective"], r["x"])

Where the established solvers still lead

On the 50 smaller MIPLIB instances, AXOS proves optimality on 3, against SCIP 16, HiGHS 15 and CBC 7, and its mean primal gap is the highest of the five runs. AXOS still finds the best solution of all four solvers on some of them. Mature MIP solvers win there with decades of presolve, cutting planes (flow covers for fixed-charge networks), conflict analysis and a very fast dual simplex. These are the next steps for AXOS.

On the small Maros–Meszaros QPs, PIQP's interior point stays faster (SGM10 0.67 s against 1.90 s for AXOS auto). AXOS's advantage grows with problem size and with the GPU.
