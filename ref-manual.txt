AXOS reference manual

Last updated: 2026/10/05

This is the whole AXOS tree: the dense tensor layer (tensorET and friends,
docs/TENSOR_SPEC.md), the sparse layer, and the LP, QP and MILP solvers.
The solver roadmap is src/solver/ROADMAP.md; benchmark results are in
benchmarks/*/RESULTS.md.

0. Building

Requirements: GNU Make, g++ with C++17 and OpenMP, Eigen 3 (tests and
reference benchmarks). Optional: CUDA toolkit (nvcc, cuSPARSE, cuDSS, cuBLAS,
cuSolver) with a host gcc that nvcc accepts (detected by `make configure`,
override with NVCC_CCBIN=...).

make test_tensor_cpu                          # dense layer, CPU only
make test_sparse_cpu / make test_sparse        # sparse matrices, CPU / CPU+CUDA
make test_solver_cpu / make test_solver        # LP + QP + MILP solvers
make axos / make axos_mpi / make test_cli      # command line, MPI, CLI test
make benchmark_dense, make benchmark_sparse, make benchmark_lp,
make benchmark_qp, make benchmark_milp
make reference_benchmarks                      # Eigen harnesses for TENSOR_SPEC.md

Pass --headless (or set HEADLESS=1, or pipe stdout) to the tests for plain text
output. The QP and MILP benchmarks live in benchmarks/qp/ and benchmarks/milp/.

1. Sparse Matrices & Direct Solves (src/sparse/)

AXOS::Sparse::Csr<T, Idx = int32_t, Store = Cpu::HostStorage> is a
compressed-sparse-row matrix (0-based, columns sorted within each row, no
duplicates, fixed sparsity pattern with changeable values). It is not a
tensorET, since almost every tensorET operation assumes dense layout;
conversion and mixed products are explicit. T is float, double or
std::complex of those; Idx is int32_t or int64_t. CsrCuda<T, Idx> is the
CUDA version (device arrays from the GPU pool). Copying between storages is
a plain conversion: CsrCuda<double> d = host_csr;

#include "sparse/sparse.h"   // (CUDA: include tensorCuda.h first if used)
using namespace AXOS::Sparse;

CooBuilder<double> b(rows, cols);
b.add(i, j, v);                     // duplicates are summed
Csr<double> A = b.build();          // sorted CSR on the host
CsrCuda<double> dA = A;             // upload
std::string bad = A.validate();     // "" when the invariants hold

tensorETCuda<1, double> x(...), y({rows}, 0.0);
spmv(dA, x, y, /*alpha=*/1.0, /*beta=*/0.0);    // y = alpha*A*x + beta*y
spmv_t(dA, y, x);                               // A^T y, via cached A^T
spmm(dA, X, Y);                                 // sparse * dense (row-major)
scale_rows_cols(dA, row_scale_ptr, col_scale_ptr);   // either may be null
row_norms(dA, out_ptr, Norm::L2);  col_norms(...);   // L1, L2, Linf
auto C = spgemm(dA, dB);            // sparse * sparse
auto N = AdAt(dA, d_ptr);           // A diag(d) A^T (normal equations)
auto At = dA.transpose();           // A.transposed() is the cached one
auto A2 = A.append_rows(cuts);      // stack rows (rebuilds the pattern)
auto v = A.values_view();           // dense 1-D view of the nonzeros
Csr<double>::from_dense(D, tol);    A.to_dense();

Mutable access to the values (values_mut(), values_view(), scaling)
discards the cached transpose; call values_changed() if you keep a raw
pointer across calls. Vector arguments must be in the same storage as the
matrix.

AXOS::Sparse::SparseLdlt<T, Idx, Store> factorizes A = P^T L D L^T P for
symmetric A stored with both triangles:

SparseLdlt<double, int32_t, Cuda::CudaStorage> ldl(Symmetry::Symmetric);
ldl.analyze(K);            // ordering + symbolic; once per sparsity pattern
bool ok = ldl.factorize(K);// numeric; call again whenever the values change
ldl.solve(rhs, sol);       // tensorET<1> vectors in the matrix's storage
size_t pos, neg, zero;  ldl.inertia(pos, neg, zero);

Symmetry::SPD requires positive pivots (factorize returns false otherwise);
Symmetry::Symmetric only requires nonzero pivots and does no numerical
pivoting, which suits quasi-definite systems such as interior-point KKT
matrices. On the CPU it is a simplicial LDL^T (dense_ldl.h) or a
multifrontal LDL^T on relaxed supernodes (multifrontal_ldl.h;
Factorization::Auto switches at 200k entries in the factor, Simplicial /
Supernodal force one), with the ordering chosen by Ordering::MinDegree
(approximate minimum degree, amd_order.h; Natural / ExactMinDegree /
NestedDissection are also available). The multifrontal code factors
independent subtrees in parallel and uses OpenMP inside large dense fronts;
because those kernels are floating-point bound, set OMP_NUM_THREADS to the
number of physical cores (16 hyperthreads were about 30% slower than 8).
set_pivot_regularization(signs, eps) enables dynamic per-pivot
regularization for quasi-definite systems. On CUDA it uses NVIDIA cuDSS
(cudss_solver.h; build with -DCUDSS_WITH -lcudss, -DCUSPARSE_WITH
-lcusparse).

Tests: make test_sparse_cpu / make test_sparse (CUDA + cuDSS).
The LP, QP and MILP solvers built on this are in src/solver/ (see 2).

2. Optimization: LP, QP and MILP (src/solver/)

One entry point for all three problem types (header only, src/solver/api.h):

#include "solver/api.h"
using namespace AXOS::Solver;

Model m = read_model("model.mps");   // MPS, or QPS (QUADOBJ / QMATRIX)
Options o;
o.time_limit = 60;        // also type, method, device, tol, gap, verbose
Result r = solve(m, o);   // ProblemType from the model: MILP / QP / LP
// r.status, r.objective, r.bound, r.x, r.y, r.gap(), r.max_violation, r.nodes
std::cout << result_json(m, r);        // or write_solution(std::cout, m, r)

Methods (Options::method):
  LP    auto     dual simplex; HPR on the GPU (or CPU) if it fails or the
                 problem is very large
        simplex  bounded dual simplex (exact vertex solution)
        ipm      Mehrotra interior point
        pdlp     restarted PDHG (first order, CPU)
        hpr      Halpern Peaceman-Rachford (first order, GPU when available)
  QP    auto     interior point when its factorization is cheap, else HPR-QP
        hprqp    HPR-QP (GPU or CPU); "hpr" is a synonym
        pdhcg    PDHCG (GPU or CPU)
        ipm      interior point (CPU)
  MILP  auto     branch and cut (presolve, probing, cuts, heuristics; with
        /bnb     Device::Gpu / Auto the GPU probes, runs feasibility-jump
                 walkers and batched strong branching)

The problem type follows from the model: MILP when a column is integer, QP
when the objective has a quadratic part, else LP. Options::type forces one
(e.g. the LP relaxation of a MILP). Objective values are in the model's own
sense (a MAX model reports its maximum), and every returned solution is
checked against the model: Result::max_violation is its largest bound / row
violation (relative to 1 + |side|), integrality included for a MILP.

Command line (build/axos; apps/axos.cpp, wrapped by apps/axos.py), the same
API behind a CLI:

    build/axos [options] file.mps|file.qps
      --method auto|simplex|ipm|pdlp|hpr|hprqp|pdhcg|bnb
      --device auto|cpu|gpu, --time-limit S, --tol E, --gap G
      --no-presolve, --no-cuts, --no-heuristics, --solution FILE
      --json FILE|-, --quiet, --verbose N, --version

The exit status is 0 for optimal, 1 for a solution without proof of optimality,
2 infeasible, 3 unbounded, 4 no solution within the limits, 5 error, 64 bad
usage. make test_cli (python tests/test_cli.py) checks the command line and
the Python wrapper on LP, QP and MILP models with known answers.

2.1 LP (src/solver/lp/)

The LP-only API is in src/solver/solver.h (include tensorCuda.h first when
using the GPU):

#include "solver/solver.h"
using namespace AXOS::Solver;

LpProblem p = read_mps_file("model.mps");      // or fill LpProblem by hand
SolverOptions opt;
opt.set_tolerance(1e-6);       // relative, PDLP convention (see model.h)
opt.time_limit = 60;           // seconds
LpSolution s = solve_lp<Cpu::HostStorage>(p, opt);       // CPU
LpSolution g = solve_lp<Cuda::CudaStorage>(p, opt);      // GPU
// s.status: Optimal, Infeasible, Unbounded (dual infeasible), IterationLimit,
//           TimeLimit, NumericalError
// s.x primal, s.y row duals, s.z reduced costs, s.primal_objective,
// s.dual_objective, s.primal_residual, s.dual_residual, s.iterations

AXOS::Solver solves
    minimize c^T x + offset   subject to  row_lb <= A x <= row_ub,
                                          col_lb <=  x  <= col_ub
with A a host Csr (see 1). Any bound may be +-Solver::kInf; equalities have
row_lb == row_ub. A maximization problem is stored negated (maximize = true).
Duals follow z = c - A^T y, with y_i >= 0 only at a row's lower bound and
y_i <= 0 only at its upper bound.

solve_lp runs presolve, then the chosen algorithm on the reduced problem, then
postsolve, so s.x, s.y and s.z are for the problem you passed in and the
reported residuals are computed on it in double precision.
opt.presolve = false skips presolve; opt.scaling = false skips the Ruiz and
Pock-Chambolle scaling.

Four methods, chosen with opt.method:

- LpMethod::Pdlp (default): a restarted primal-dual hybrid gradient method.
  It needs only sparse matrix-vector products, so it maps well to the GPU
  and to very large problems, it reaches moderate accuracy (1e-4 to 1e-6)
  quickly, and it detects infeasibility and unboundedness from iterate
  differences (the certificate needs a clear margin, about 10x the
  tolerance, so a barely infeasible problem ends at the iteration or time
  limit instead). Tight tolerances on hard or badly scaled models can take
  very many iterations. The default variant is reflected Halpern PDHG with a
  fixed step size (opt.pdlp_halpern = true; 1.3-1.8x fewer iterations than the
  adaptive-step PDHG with averaging on most models, slower on some packing LPs).
  opt.pdlp_polish = true reaches a tight tolerance by running to 1e-4 and then
  solving a primal and a dual feasibility problem from that point (helps some
  models, hurts others; off by default).
- LpMethod::Simplex: a CPU dual simplex (sparse LU basis with hypersparse
  FTRAN/BTRAN, dual steepest edge, bound flipping ratio test, artificial-bound
  phase 1, Devex primal cleanup). Gives a basic solution, detects infeasibility
  and unboundedness, and solves all 25 netlib models. It is the method MILP
  warm starts (SimplexBasis).
- LpMethod::Ipm: a primal-dual interior-point method (Mehrotra
  predictor-corrector) on a regularized augmented KKT system, factorized by
  SparseLdlt (cuDSS on CUDA, AMD-ordered LDL^T on the CPU; see 1). It gives
  high accuracy (1e-8 and better) in few iterations. It has no infeasibility
  or unboundedness certificates: a failed run reports NumericalError or
  IterationLimit. Its cost is dominated by the sparse factorization, so it is
  fast on structured LPs and slow when the KKT factors fill in almost
  completely (random sparse graphs, large packing LPs). On the CPU it solves
  the m x m normal equations instead of the augmented system when A has no
  free or dense columns (opt.ipm_normal: 0 choose, 1 force, -1 never).
  opt.ipm_max_iterations and opt.ipm_ordering (0: AMD, 1: nested dissection on
  the GPU) tune it. opt.crossover = true follows an optimal IPM run with a
  simplex started from the interior point, to return a basic solution.
- LpMethod::Auto: if the predicted interior-point factorization is cheap, the
  interior-point method, then the dual simplex, then PDLP. If it is expensive
  (CPU only; predicted from the symbolic analysis), the dual simplex first for
  a slice of the predicted interior-point time, then the interior-point method,
  then PDLP. The time limit is shared. (Everything except PDLP alone runs
  after presolve.)

"Optimal" means the tolerances in opt hold on the ORIGINAL problem and,
additionally, LpSolution::error_bound <= 10 * eps_gap * (1 + |objective|),
where error_bound = gap + ||dual residual|| ||x|| + ||primal residual|| ||y||.
This is what stops a badly scaled model from being reported as optimal just
because its residuals are small relative to ||c||.

On the 25 netlib LPs shipped with the HiGHS repository: the dual simplex
and Auto solve all 25 (19 optimal to 1e-7..1e-9 relative objective error,
6 infeasible detected; greenbea, optimal variables near 3e8, needs the simplex);
the interior-point method solves 18 of the 19 feasible ones in 0.1 ms to 0.2 s;
PDLP at 1e-6 solves 17 of them. Compared with HiGHS' dual simplex the times are
within 1.2x to 2.4x on the larger models (greenbea 5.6x). See
benchmarks/solver/RESULTS.md.

Other pieces: write_mps() (round-trips read_mps), Presolve (class; reduced()
and postsolve()), compute_scaling/apply_scaling/unscale_solution, and
evaluate_solution(p, x, y) to check any candidate (x, y) on the host.
MPS support: NAME, OBJSENSE, ROWS (extra N rows are dropped), COLUMNS with
MARKER INTORG/INTEND, RHS, RANGES, and the bound types UP LO FX FR MI PL BV
LI UI. Integer markers are read into LpProblem::is_integer; the LP solver
ignores them (they drive the branch-and-cut in 2.3).

Tests: make test_solver_cpu / make test_solver (includes real netlib models
from tests/data). Benchmarks: make benchmark_lp; real instances:
benchmarks/solver/fetch_netlib.sh, then build/run_mps --method ipm|pdlp|simplex|auto
build/netlib/*.mps (compare with benchmarks/solver/netlib_reference.py, which
needs highspy).

2.2 QP, convex (src/solver/qp/)

#include "solver/qp/solve_qp.h"    // QpProblem, QpOptions, solve_qp
using namespace AXOS::Solver;

QpProblem q = read_qps_file("model.qps");   // LpProblem + Q (via io/qps.h)
QpOptions qo;
qo.method = QpMethod::HprQp;    // HprQp, Pdhcg, Ipm, Auto
qo.use_gpu = qp_gpu_available(); qo.auto_device = true;
QpSolution s = solve_qp(q, qo);
// s.x, s.y, s.z; s.kkt() = max(rel_primal, rel_dual, rel_gap); s.iterations

QpProblem is an LpProblem plus Q (n x n symmetric, both triangles stored,
empty = LP); the objective is offset + c^T x + 0.5 x^T Q x over the same
constraints and bounds. QpMethod::Auto uses the interior point (qp_ipm.h, CPU,
augmented system on the multifrontal LDLT) when the KKT factorization is
cheap (ipm_auto_flops), else or when it fails HPR-QP (GPU for large problems).
QpOptions::auto_device / use_gpu pick the device; gravity of the thresholds is
in gpu_min_work and gpu_min_work_hard. With qo.comm (MPI, qp_dist.h,
-DAXOS_ENABLE_MPI) HPR-QP holds a block of the constraint rows per rank and
needs one Allreduce of A^T y per iteration. Benchmarks against HPR-QP.jl,
PDHCG.jl, OSQP, Clarabel, HiGHS, PIQP and SCS are in benchmarks/qp/README.md.

2.3 MILP (src/solver/milp/)

#include "solver/milp/solve_milp.h"   // MilpOptions, MilpSolution, solve_milp
using namespace AXOS::Solver;

MilpOptions mo; mo.gap_rel = 1e-4; mo.time_limit = 600;
MilpSolution s = solve_milp(p, mo);   // p: LpProblem with is_integer set
// s.status, s.x, s.objective, s.bound, s.gap(), s.nodes, s.lp_iterations

Branch and cut: presolve (LP reductions, MIP coefficient tightening, domain
propagation, double probing on the binaries), a root that runs the dual
simplex with Gomory mixed-integer cuts from the tableau and c-MIR cuts from
the rows, reduced-cost fixing, primal heuristics (feasibility jump, rounding,
fix-and-propagate, diving, objective feasibility pump, RENS, RINS), and
reliability-pseudocost branching with strong branching under best-bound search
with plunging. The tree runs on the CPU; the GPU (MilpOptions::gpu) probes the
binaries at the root, runs feasibility-jump walkers and batched PDHG strong
branching, whose Lagrangian duals are valid child bounds. See
benchmarks/milp/README.md for MIPLIB 2017 results against HiGHS, SCIP and CBC.
